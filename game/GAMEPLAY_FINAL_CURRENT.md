# 사건파일 No.464 — 최신 최종 진행 방식 (사용자 직접 지정)

> **현재 상태: 새로운 최종 진행 방식 입력 대기.** 사용자가 2026-11-12에 "이제부터 내가 말해주는 게 최종 방식이야. 그전 건 적용하지 마"라고 지시함.
>
> **가장 중요한 원칙:** 이 지시 이후 사용자가 새로 명시하는 게임 진행 규칙만 최종안에 반영한다. 이전 대화, `game/GAMEPLAY_FLOW_DRAFT_20261112.md`, 과거 `UI_FLOW.md`의 진행 방식, 각종 예시 및 기존 User Lock 문구를 **새 게임 진행 방식의 기본값으로 자동 승계하지 않는다**. 사용자가 새로 말하지 않은 내용은 **미정**으로 기록한다.

## 현재 최종안 상태

- 새로운 게임 진행 단계/턴 규칙/UI 흐름: **아직 상세 설명을 받기 전**.
- 사용자가 지금부터 직접 정하는 내용이 이 파일의 최신 본문이 된다.
- 이전 초안은 **참고용 기록**으로만 남겨 두되 구현·설계에 적용하지 않는다.
- 이전에 구현한 Unity 맵/캐릭터/원본 에셋을 이 지시만으로 삭제·변형·초기화하지 않는다. 게임 진행 규칙 폐기와 에셋 삭제는 별개의 조치다.
- 새로운 규칙과 과거 기술·데이터 구현 사이에 충돌이 생기면 **새 사용자 지시를 우선**하되, 기존 프로젝트 파괴나 임의 마이그레이션은 하지 말고 영향을 보고한다.
- 이 문서를 작성했다고 Unity 코드·씬·실행 동작이 바뀐 것은 아니다.

## 이후 업데이트 절차

1. 매 요청 시작 시 GitHub `main` 최신 SHA와 관련 파일을 확인한다.
2. 사용자가 새로 **직접 지정한 내용만** 이 파일에 반영한다. 추측, 이전 구상, AI 제안은 확정 규칙으로 옮기지 않는다.
3. 사용자가 새 방향을 수정하면 같은 파일의 현행 내용만 최신화한다. 필요 시 변경 이력을 간단히 남긴다.
4. 새 최종안의 구현은 사용자가 명시적으로 요구할 때 별도 수행한다. 기획만 정하는 도중 Unity 게임 진행 코드를 임의 수정하지 않는다.
5. 작업 완료 시 실제 GitHub 커밋 및 `main` 반영 여부를 확인하여 SHA를 보고한다. 충돌 시 강제 초기화/강제 푸시 금지.
6. 별도 명시 요청 전 Play Mode·기능 테스트·게임 빌드는 하지 않는다.
