# 대화 턴마다 이름표·대사 동기화 및 하단 UI 배치 보정

2026-11-10 · `mystery` · Unity 6 / Windows PC

## 대화 흐름

- 플레이어가 질문을 보내면 화면의 **이름표는 '탐정'**, **대사 본문은 실제 입력한 질문**으로 즉시 교체한다. 전송과 동시에 탐정 질문이 NPC 답변으로 덮이지 않도록 짧게 표시한다.
- 승인된 NPC 답변이 도착하면 약 0.8초 뒤 **이름표는 현재 NPC 이름**, **본문은 해당 NPC가 실제로 한 승인된 답변**으로 바뀐다.
- 사건이 미승인이라 NPC 답변이 없으면 이름표에 **'안내'**를 표시하고 NPC의 가짜 대사처럼 보이게 하지 않는다.
- 답변 어댑터가 아예 없으면 탐정의 질문을 유지한다.
- NPC나 사건 테마를 바꿀 때는 **해당 NPC와 사건의 가장 최근 대화 기록**을 이름표/본문에 함께 복원한다. 대화 기록은 기존 사건/인물별로 계속 분리한다.
- 저장/불러오기 후에도 각 NPC의 가장 마지막 기록에 적힌 화자와 대사를 보여 준다.
- 이 변경은 '범인 자동 생성'이나 미승인 사건 해제가 아니다. `approved: false` 3건 유지.

## UI 배치

- 이름표 `Frame/NpcName`은 **왼쪽** `(-590, 125)`(Frame 로컬 좌표), 크기 `400×54`로 변경. 더는 오른쪽 NPC 초상화 밑에 나타나지 않는다.
- 대사 본문 `Frame/NpcDialogue`는 `(0,0)`에 `1500×220`, 이름표 밑에 표시한다.
- `QuestionInput`와 `SendButton`을 루트 Y=115로 올리고, `Status`를 Y=174로 옮겨 **장식 테두리와 입력창·상태·본문의 간격**을 확보한다.
- Edit Mode에서 보이는 위치와 Play Mode에 적용되는 위치를 **프리팹 및 `DialogueCinematicView.ApplyLayout` 양쪽에 동일하게 기록**했다.
- 기존 글꼴·NPC 원본 6개·테마 프레임 3종 및 초상화 매핑은 변경하지 않았다.

## 1회 Play Mode 실화면 검증

1. GitHub 최신 브랜치의 `DialoguePanel.cs`, `DialogueCinematicView.cs`, `DialoguePanel.prefab`만 로컬에 동기화. 로컬 SDF 폰트 2종과 열린 씬의 미저장 편집 보존.
2. Unity Edit Mode에서 오류·경고 0개와 Missing Script 0개를 먼저 확인.
3. 승인 잠금 `approved: false` 유지 상태에서 **Play Mode에 1회만 진입**.
4. 실제 `DialoguePreview`에서 탐정 질문 제출 직후 **'탐정'과 질문 본문**, 이어 **'안내'와 미승인 사건 안내문**으로 바뀌는지 확인. 가능하다면 이 두 시점을 실제 Game 화면 PNG로 각각 캡처하되, Play Mode 재진입은 하지 않는다.
5. 1280×720에서 **왼쪽 이름표**, 하단 프레임의 입력 플레이스홀더·상태·대사 간 잘림/겹침 확인. 원본 NPC 이미지는 우측에 보존.
6. Play Mode 종료. **NPC 승인된 실제 답변·장문 대사·맵 블러**는 이번 테스트로 검증할 수 없으므로 미검증으로 명시.
7. 실제 Unity Game 캡처 외의 합성 화면은 테스트 결과 이미지로 제시하지 않는다. EXE 빌드 금지.

**테스트 상태:** 이 커밋은 원격 소스·프리팹 수정만 수행했다. Unity Play Mode, 실제 컴파일, 스크린샷은 로컬 도구에서 수행해야 하며 아직 성공 주장 불가.
