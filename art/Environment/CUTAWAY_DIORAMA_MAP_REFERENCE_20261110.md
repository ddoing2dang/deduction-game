# 사건파일 No.464 — 지붕 없는 3D 컷어웨이 디오라마 맵 연출 기준
2026-11-10 · 사용자 제공 크라임씬 세트 이미지 4장 참고 · **아트 방향 확정 / Unity 미구현·미검증**

## 0. 사용 범위와 저작권
사용자가 제공한 이미지에서 **공간을 보여주는 방식만** 참고한다. 특정 방송의 세트 배치·자막·로고·시그니처 효과·텍스처·오브젝트 조합을 복제하거나 원본 스틸을 게임 에셋/저장소에 저장하지 않는다. 게임은 독자적인 호텔·크루즈·음악방송 테마로 디자인한다.

## 1. 이미지에서 가져올 공간 연출 문법
1. **검은 배경의 독립 디오라마**: 전체 건물/층/방이 하나의 모델 세트처럼 떠 있는 연출. 게임 월드 바깥은 검거나 매우 어둡게 처리하되 방 안은 자연스러운 간접광·실용등으로 충분히 밝게.
2. **지붕 제거 + 카메라 쪽 전면 벽 컷어웨이**: 실제 벽 두께·창틀·문틀·난간은 남기고 시야만 확보한다. 방 전체를 무벽 평면으로 만들지 않는다.
3. **깊게 내려다보는 쿼터뷰**: 일반적인 얕은 30~45° 디오라마보다 고각. 기준 시안은 수평면 기준 카메라 고도각 **60°**, 비교 후보 **55°/65°**, 방별 조정 허용. 수평 회전은 약 **45° 또는 225°**, 맵이 가장 잘 보이는 방향으로 확정.
4. **각 공간의 세트디자인이 확연히 구별**: 바닥 재질·가구 배치·대표물·조명·색감·시각적 높이/깊이 차이를 쓴다. 동일 기본 방 프리팹을 색만 바꿔 늘리지 않는다.
5. **모형 전체를 우선 보여줌**: 하나의 높은 카메라에서 건축 전체의 관계를 이해하고, 방 선택 시 자연스럽게 확대하여 조사. 캐릭터 자유 심문·추궁 시 별도의 3D 배경+2D 상반신 시네마틱으로 전환 가능해야 한다.
6. **경계 강조는 UI로 제한**: 공간 외곽선·선택 방 하이라이트는 선택 또는 탐색 안내 때만. TV 방송 자막처럼 모든 공간 이름을 화면에 크게 고정하지 않는다.
7. **복수 층/데크는 선택적 분리형 단면**: 호텔 1F/2F, 크루즈 3/4데크는 전체맵에서 나란히 놓은 '전시 모드' 또는 층별 포커스 모드를 고려하되, 실제 이동 시간/방 연결/사건 진실은 변경하지 않는다. 움직이는 층 표현은 **연출만** 담당한다.
8. **검은 배경이 저품질의 은폐 수단이 되지 않도록**: 조명·PBR 텍스처·노멀·모서리 베벨·가구/천장 단면·그림자·접지 상태를 확대샷에서도 확인해야 한다.

## 2. 시점과 카메라 운용
| 모드 | 권장 연출 | 데이터 제약 |
|---|---|---|
| WORLD_OVERVIEW | Orthographic, 시작 고도각 60°, 검은 주변 배경, 집 전체가 보이는 앵글 | 탐색 공간 8개 고정, 통로는 추가 조사 방 아님 |
| FLOOR_OVERVIEW | 층/데크를 각각 독립된 디오라마 패널처럼 보여줌. 교체/전환 애니메이션 | 호텔 4+4, 크루즈 5+3; 물리 위치/시각 연출 분리 |
| ROOM_FOCUS | 방으로 이동, 건축 모서리와 높이를 읽기 좋은 고각 55~65°, 필요하면 조금 더 낮춰 입체감 확보 | roomId 선택만; 미발견 증거 강조 금지 |
| OBJECT_INSPECT | 실제 3D 물체 근거리 프레이밍, 필요 시 Perspective로 전환 | 승인된 evidenceId 및 이미 발견한 내용만 표시 |
| NPC_DIALOGUE | 현재 방의 3D 배경+인물 상반신·테마 대화창 | AI는 승인 대사만 선택, 범인 여부 UI 암시 금지 |
| CONFRONT | 초상 컷인+진술/물증 패널/확실한 추궁 효과 | statementId/evidenceId 조건 확인 후 반응 |

**카메라 수치들은 제작을 위한 초기값**이다. 사용자가 승인한 개별 씬 스크린샷이 기준이며, 시점 숫자 자체가 완성도를 보장하지 않는다. 카메라 yaw/orthographicSize·focus는 씬과 화면비에 따라 조절한다.

## 3. 건축물 구조
- 실제 3D 벽·천장·바닥·기둥·걸레받이·문턱·난간·벽 장식·창틀을 제작하고 overview용으로 **지붕과 카메라 가까운 가림 벽만 선택적으로 비표시**한다.
- 방 경계는 바닥/벽체 두께로 명확히 구분. '방마다 사각 테두리'만 입혀 구조물을 생략하지 않는다.
- 모든 방 오브젝트는 월드 공간에 실재. 표시 층 분리 시 시각적 루트/카메라만 재배치하고 사건 진실 데이터와 길찾기 노드는 유지.
- 최종맵 바깥의 검은 부분은 배경 연출. 실제 지오메트리의 누락·공중에 떠 있는 가구·빈 방을 숨기는 수단으로 사용 금지.
- 서재·생활실·창고·로비처럼 용도가 다른 공간은 **밀도와 여백을 다르게**. 소품이 과밀해 수사 핫스팟이 가려지지 않게 한다.

## 4. 테마별 기존 확정 구조를 이 프레임에 적용
| 테마 | 전체 지도에서의 디오라마 배치 | 고유 디테일 |
|---|---|---|
| HOTEL | 1층(로비+101~103)과 2층(201~204)을 옆으로 분리해서 볼 수 있는 이중 층 단면. 204는 현장 | 고급 호텔 로비 중앙 계단, 브라스, 천장 몰딩, 월넛, 대리석, 품질 높은 객실 가구 |
| CRUISE | 길고 좁은 선박 3데크 5방/4데크 3방의 분리형 선체 단면. 앞뒤 계단 2곳을 연결 UI로 인식 | 둥근 선실 벽/창, 난간, 선실문, 금속/목재 접합, 해양 전용 장식 |
| MUSIC_BROADCAST | 단층 U자형 양 날개 6개 개인 대기실+중앙 대기홀+가까운 VIP-01 현장. 위에서 U자 동선이 읽힘 | 조명 거울, 의상·전선·마이크·스피커, 무대 뒤 대기실 인테리어 |

세 테마 모두 8개 **조사 가능 공간**. 복도/계단은 이동 노드이므로 추가 공간으로 세지 않는다. 각 NPC 객실과 사건실 표시 번호는 `game/maps/theme_room_layouts.v1.json`이 정본.

## 5. 고품질 통과 조건
- **최소 한 컷의 전체맵**에서 건축 배치·문 방향·층수·8개의 조사 공간 구분이 읽혀야 한다.
- **최소 한 컷의 확대뷰**에서 고급 가구의 모서리, 손잡이, 패널, UV, PBR·유리/금속/천·그림자·생활 소품이 실제로 설계되어 있어야 한다.
- 정상 카메라에서 벽·난간이 조사 물체를 가리는 경우 부분 컷어웨이/투명화/카메라 이동으로 해결. 무조건 모든 벽을 삭제 금지.
- 저폴리 모델은 기본 비례/더미 검토에 한정; 심사용 완료 이미지에는 사용자 승인 없이 사용 금지.
- **검은 배경만으로 품질 통과 금지**. 네거티브 공간과 실내 광량을 동시에 확보.
- 큰 방을 텅 비우거나 똑같은 방을 복제한 뒤 이름표만 바꿔 넣는 방법 금지.
- 각 방 최소 하나의 대표물과 충분한 건축/생활 디테일, 해당 방 역할에 맞는 시선 유도.
- 화면 글자는 실제 수사 UI만 사용: 방명은 선택/호버/지도 모드에서, 증거/범인 식별은 규칙에 맞춰 공개.
- 화면 성능 목표와 최종 조명/LOD 최적화는 실제 PC/Unity 프로젝트에서 확인해야 하며 **현재는 미측정**.

## 6. 제작·검증 순서
1. 기존 Unity 프로젝트 복제본을 GitHub에 연결하고 Unity MCP 클라이언트 실제 연결 확인.
2. HOTEL H00 로비 1개에 **월드 전체 보기 + 방 확대** 두 카메라 구도만 우선 제작; 일단 이 첫 공간을 시각적 품질 원점으로 삼는다.
3. 고품질 건축물/재질/소품이 부족하면 **작업 중단 및 준비물 목록 작성**, 저품질 더미로 대체 완료 금지.
4. 사용자에게 overview·room focus·detail 각 시안으로 확인받은 후, 검수한 제작 규칙으로 나머지 공간 확장.
5. 이후 호텔 1F/2F 전체 연결, 크루즈, 음악방송 순서. 사건/의심/심문 장면은 실제 사건 지식·대사 조건과 별도 연동한다.
6. 동일 기술 검증 실패 2회 → 즉시 중지, 원인·마지막 성공 커밋·부족한 준비물 기록. **실제 Unity Play Mode·기능 테스트·빌드는 추가 요청 전 하지 않음**.

## 7. 현재 상태
이 문서는 참고 이미지의 공간 문법을 독자 설계에 번역한 **아트 스펙**이다. 참고 스틸을 GitHub에 업로드하지 않았고, Unity 프로젝트/씬·카메라 렌더/오브젝트 품질을 실제로 확인한 상태가 아니다.
